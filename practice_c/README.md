## 🚀 实战工作流与规则 (Workflow)

```mermaid
graph LR
    A["1. 下发需求卡<br/>(明确核心逻辑与测试要求)"] --> B["2. 独立全量开发<br/>(从 #include 到 main 测试)"]

```

### 1️⃣ 需求发布 (Task Brief)
每次开启实战时，会在本目录下建立题目文件（如 `p01_singly_linked_list.c`），文件顶部会包含清晰的**需求规格说明书**：
* **核心考察点**：本次重点攻克的算法逻辑（如指针逆序、4步黄金链接律、双向解绑等）。
* **接口设计约定**：函数签名、输入参数、返回值含义。
* **必测边界场景**：例如空链表、单节点、首尾极限操作等。

### 2️⃣ 独立全量编码 (Your Full Implementation)
你将独立完成整个文件的编写，包含：
1. **头文件引入**：`#include <stdio.h>`, `#include <stdlib.h>` 等；
2. **结构体定义**：`typedef struct Node { ... } Node;`；
3. **辅助功能函数**：节点创建、格式化打印等；
4. **核心算法实现**（重点攻坚）；
5. **测试驱动 `main()`**：自行设计用例并进行结果校验；
6. **内存安全释放**：全生命周期闭环。

### 3️⃣ 严苛代码审查与联调 (Code Review)
完成后，AI 将以**最严格的工程标准**进行审查：
* **编译检查**：使用 `gcc -Wall -Wextra` 确保 0 警告、0 错误；
* **逻辑正确性**：验证核心算法在各种极端条件下的表现；
* **内存安全性**：排查是否存在内存泄漏（Memory Leak）、野指针（Dangling Pointer）或 Use-After-Free；
* **测试用例覆盖度**：评估你编写的测试是否覆盖到了全部边界场景。
